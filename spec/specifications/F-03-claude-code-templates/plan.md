# Implementation Plan — Claude Code templates (F-03)

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

Scope note: the flat generator, flat layouts, flat `planGeneration`, flat `checkReply` and flat `validateConfig` stay in place until F-07 (`stories.md` US-007). Every new function lives in `source/packages/core/src/pipeline/`, and the new layouts live in `source/templates/base/` and `source/templates/claude-code/`.

## Rationale

- **Layouts first (T002–T004):** every later task reads them, and the placeholder table in the README is the contract that AC-025 checks. Each layout task adds its own placeholders to that table, so the table is never behind the layouts.
- **Command layouts before plan (T003):** the step and route text is built in code, so the builders are tested on their own (AC-005, AC-006) before `planGeneration` uses them.
- **`planGeneration` in three steps (T005–T007):** the order and paths come from the pipeline `generate` that F-02 built. T005 adds the entries that come from the command and base layouts, T006 adds the agent and rule entries, and T007 adds the error paths. Each step stays small and green.
- **`checkReply` in three steps (T008–T010):** presence and paths come first, then content, then the reply's shape and ordering. Each step's findings depend only on the plan from T005 and T006.
- **Stack-neutral checks (T011) after the layouts exist:** the check runs over the finished layouts, so a failure points at a real layout, not a planned one.
- **Separation (T012) last:** it proves the flat code and the API are untouched, which only holds once every new module is in place.
- **Docs (T001, T013):** T001 corrects `features.md` now, because the Mermaid and rule-entry lines are wrong for anyone reading the plan. T013 updates the README once the layouts are final.
