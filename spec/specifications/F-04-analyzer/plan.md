# Implementation Plan — Analyzer: structural checks and LLM review (F-04)

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose. The staged diff of a task stays under the 400-line size guard, counting deletions.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

Scope note: the `/generate` route, its flat reader and caps (`readConfig`, `capProblems`, `validateConfig`, `planGeneration`) and the flat catalog stay in place until F-07. Every new analysis function lives in `source/packages/core/src/pipeline/analyze/` (and the pipeline caps in `source/packages/core/src/pipeline/caps.ts`). The pipeline module is reached from the root as the `pipeline` namespace (decision 22), so its names do not collide with the flat model's names.

## Rationale

- **Decision first (T001):** the namespace export (T002) and the analysis module are code that depends on decision 22, so the decision is recorded before code depends on it (`general.md`, Architecture).
- **Core checks before the route (T002–T010):** every check is pure and tested on its own, with the same list ordering from T003. Each later check adds one function to the list in `pipeline/analyze/index.ts`, so each task stays small and green.
- **Reuse, not copy (T002–T003):** the refusal checks already exist for generation. T002 extracts their list into `configProblems`, and `refuseInvalidConfig` keeps its behaviour, so the analysis and the generator refuse the same things.
- **API after core (T011–T016):** the reader, the prompt and the analysis use the core functions from T002–T010. The route is changed last, once its parts are tested, so `/analyze` is never left half-wired.
- **Flat removal after the API stops importing it (T017–T022):** the flat analyzer is deleted only once nothing in `source/apps/` imports it (T016 confirms). The deletion is split into six tasks, because the flat analyzer and its tests are about 1,850 changed lines; each task stays under the 400-line guard (test groups first, then sources).
- **Scan (T023):** a test that no file in `source/apps/` imports a flat analysis export keeps the removal from regressing.
- **Docs last (T024):** the text describes the finished route; decision 22 is recorded earlier (T001).
