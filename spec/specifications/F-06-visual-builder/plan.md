# Implementation Plan — Visual builder: global map and workflow tabs (F-06)

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

## Rationale

- **Docs first (T001).** The library and the disabled-condition rule are decisions. `general.md` requires them in `architecture.md` §5 before code uses them.
- **Core before web.** The builder depends on core for the model, the defaults and the cycle rule. Keeping the rules in `packages/core` (pure, no I/O) lets the API use the same rule later and keeps the web logic testable in Vitest without a DOM.
- **The model change is one task (T002), and its effects are a second (T003).** The `enabled` flag on conditions touches the parser, the catalog, the selectors and about thirteen test fixtures across core and the API. T002 keeps the type and parser change together, and T003 covers the checks and output that must ignore a switched-off condition. T003 is kept apart because its tests are about generated output and analysis, a different reviewer focus.
- **State before views.** Each state module (T005, T007, T008) is pure and tested in Vitest. The views (T010 to T013) only render the read models and call the state functions, so their correctness rests on the tested logic, plus typecheck, build and the device checks for AC-019 and AC-036.
- **Map before tab.** The map (T005, T006, T010, T011) is independent of the step editing, so the two can be separate commits. T012 and T013 come last, because they use both.
- **Library use.** `@xyflow/react` is recorded in T001 and installed in T010, the first task that imports it. No other library is added.
- **App wiring last (T014).** It needs the views and the builder state, and it changes `to-config.ts` from reading the defaults to reading the state, so F-05's brief tests are re-run there.
- **Device criteria.** AC-019 (map layout and drag) and AC-036 (inspector beside the diagram) are `[device]`. They are built in T010 and T013 and go into the manual checklist in Verify.
