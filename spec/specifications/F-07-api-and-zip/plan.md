# Implementation Plan — API: analyze and generate, zip download (F-07)

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose. The staged diff of a task stays under the 400-line size guard, counting deletions. Deletion-only tasks are split by directory where a directory alone would go over.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

Scope note: the new generation path is built beside the flat one (decision 19), in files named `pipeline-service.ts` and `pipeline-prompt.ts`, so every commit stays green. The flat path is removed in T008–T018, after the route is switched in T004. The web app is not changed. Its flat imports (`parseProjectConfig`, `INPUT_CAPS`, `DEFAULT_STEP_CATALOG`, `ConfigProblem`) stay until F-05.

## Rationale

- **Decision first (T001):** pipeline-only `/generate`, the duplicate-path 500 and the flat model kept for the web app are architecture choices; they are recorded before code depends on them (`general.md`, Architecture).
- **New path beside the flat one (T002–T007):** the pipeline prompt, service and route behaviour are built and tested while the flat path still exists, so each commit is green. The route is switched in T004 and its criteria are tested in T004–T007.
- **Pure parts before the route:** the prompt (T002) and the service (T003) take fakes, so the retry and reply rules are tested without HTTP. The route (T004) only maps results to status codes.
- **Renames after the flat files are gone (T008–T009):** the new files get their final names only once the flat files with those names are deleted, so there is one `service.ts` and one `prompt.ts` in the end.
- **Flat removal in the order of the consumers (T008 → T016):** the API stops importing the flat core (T008–T011) before the core flat modules are deleted (T012–T015). The root-exports test (T016) keeps the modules the web app needs.
- **Templates after the code (T017–T018):** the templates are read by the flat generator until T008 and by no code after it.
- **Docs last (T019):** the text describes the finished state; decision 23 is recorded earlier (T001).
