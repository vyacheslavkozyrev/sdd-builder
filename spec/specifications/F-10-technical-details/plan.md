# Implementation Plan — Technical details step (F-10)

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

## Rationale

- **Starting point.** The F-10 code of the earlier build was removed in commit `58ef413` ("start the build over"). Nothing of it is reused: the tasks write each file again. The earlier F-10 commits (`7bbe15f`, `a76731d` and the ones after) stay in history and may be read with `git show <sha>:<path>` as a reference.
- **Order.** T001 is pure logic with no React, and every later task reads its limits, its id rule and its messages from it. T002 extends the wizard state the step reads and writes. T003 is the stack and architecture part of the step, with no dialog. T004 is one rule block, and T005 is the list around the blocks, with the Add limit and the Remove confirmation. T006 wires the step into the wizard and the app, so it comes after the step body. T007 is documentation, last, once the behaviour is in place.
- **The id messages.** Owner decision of 2026-11-20: the parser refuses a rule id that is not file-safe or is over 60 characters (`pipeline-schema.md` §2, `source/packages/core/src/pipeline/check/primitives.ts` `readId`). The wizard shows a message on the block and keeps Next enabled; the analysis (F-14) reports the refusal. The three messages are checked in the order of T001: a name with no letter or digit is the first case, so an upper-case non-ASCII letter such as `É` counts as "no letter or digit" because the id rule only admits `a–z` and `0–9`.
- **Duplicates.** A block whose name gives an invalid id shows its own message only, not the duplicate message (AC-019 negative case). Two blocks with a valid id that is the same show the duplicate message.
- **Where the rules live.** The limits, the id rule, the messages and the duplicate flags are view-model logic in `source/apps/web/src/wizard/technical.ts`, not in `core`. The configuration built from these values, including the rule list as `ProjectConfig.rules`, comes with F-13 and F-14, which reuse these functions. `core` stays free of UI concerns, and `web` does not depend on `api`.
- **Rule list keys.** Rule blocks are an ordered list in the wizard state, each field is controlled, and the list is rendered with its index as the key. Removing a block re-renders the blocks after it from state.
- **Libraries.** Only `@mui/material` (`TextField`, `Button`, `Dialog`, as F-07 to F-09 use it). No new dependency. This matches `architecture.md` §5.
- **Testing without a DOM.** As in F-07 to F-09, the web package has no DOM test library. Component tests render with `react-dom/server` and check markup; behaviour is checked by finding the `TextField`, `Button` or `Dialog` element in the React element tree and calling its handler with a fixed value (the same approach as `WizardNav.click.test.tsx`). No test uses the wall clock, the network or browser storage.
- **Counting.** Code points are counted with `Array.from`, as in `project.ts`; the cut is `limitToCodePoints`, so a surrogate pair is never split.
- **AC-007 (no trim) and the configuration function.** AC-007 also says the architecture is not trimmed when the configuration function is called. No such function exists before F-13, so T002 proves the first half (Next, Prev and restart keep the text as typed). Verify records AC-007 as covered for the reducer only until F-13 adds the function. This is a known gap, not a change to the stories.
- **Open for the owner (not blocking).** The screens leave three layout points open (`spec/design/features/F-10-technical-details/screens.md`, "Open points for layout review": inner scroll of the rule list, block height at three or more blocks, clipped 100-character name), and the rule name help line on each block is still undecided (`progress.md` Deferred Findings). The three id messages of 2026-11-20 are not on the approved screens; their wording is set in T001 and shown on the block in T004. The owner can confirm the wording or ask for a screen before Verify.
- **Scope.** No Analyze, no configuration build and no storage (F-13, F-14; decision 13). The placeholder stays on steps 3 and 4 (F-11 to F-13 replace it).
