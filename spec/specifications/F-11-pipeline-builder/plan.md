# Implementation Plan — Pipeline builder (UI only) (F-11), written 2026-11-20

Written from the approved stories (`stories.md`, 8 stories, 45 criteria, with US-008 aligned to the approved screens on 2026-11-20) and the approved screens (`spec/design/features/F-11-pipeline-builder/`, committed version `5dd262d`). The earlier plan (2026-11-18) is in git history and is not followed: its code was removed before this reset.

Each task is **one implement → review → test → commit cycle** and produces exactly one commit. Rules for tasks:

- **Small:** about 50–200 changed lines, one clear purpose.
- **Green:** the repository builds and all tests pass after the task.
- **Tests travel with the code:** in the same task.
- **Ordered:** a task never depends on a later task.
- **Traceable:** each task names the acceptance criteria it covers.

## Rationale

- **Order:** pure logic first (T001–T014): the builder rules are Vitest tests with no DOM, so each rule is tested before any screen uses it. The field rules reuse `parseProjectConfig` from core, so refusal wording comes from the parser (stories AC-028), and no rule is written twice. Then the state (T014), then the components from the outside in: tabs (T015), canvas (T016–T017), panels (T018–T020), marks (T021), wiring (T022). Docs last (T023), as the behaviour is then known.
- **Core untouched:** `analyzeStructure`, `defaultPipeline` and `parseProjectConfig` are exported by `source/packages/core` already (F-02, F-03). No core change is planned; if the parser refuses a value the stories need, the task stops and an Amendment is proposed.
- **Libraries:** `@xyflow/react` 12.12.1 (approved in `architecture.md` §5, already in `source/apps/web`) draws the canvas; `@mui/material` and Emotion are approved and used for the panels and buttons. No new library.
- **Styling:** every component's style object comes from a getter that takes the theme (`web-styling.md`); colours only from the palette in `theme.ts`. The `style-rules` test must pass after every task.
- **Dependencies:** F-02 (model and parser), F-03 (`analyzeStructure`), F-07 and F-08 (layout and stepper), F-10 (rule list for rule tags, read from the wizard state). All four are complete.
- **Device criteria:** AC-006, AC-008, AC-013, AC-014, AC-016 and AC-035 (red box) are drawn in T016–T017 and checked in the browser at Verify (checklist). The drop and repoint gestures are proved at the logic level (T003, T004) and in the React Flow wiring tests (T017).
- **Stories and screens:** the approved screens do not draw the delete-connection confirmation, the refused flow name and body, or the red blocker box in the same state. Their criteria are proved by tests (AC-018, AC-020, AC-022) or by the Verify checklist (AC-035).
